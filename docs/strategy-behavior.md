# 两种 Maker 策略行为说明

本文描述当前系统里的两种策略：

- `BID_ASK_MAKER · 买一/卖一挂单`
- `FEE_AWARE_MAKER · 手续费保护 Maker`

重点说明：什么时候会买、什么时候不会买、买到以后怎么卖、卖单超时怎么处理、重启后怎么处理，以及典型例子。

> 说明：本文按当前代码行为整理。它不是收益承诺，也不是交易建议，只是为了方便排查控制台状态和策略行为。

---

## 一句话区别

| 策略 | 核心目标 | 买入价格 | 卖出价格 | 是否考虑手续费保本 | 是否限制追高 |
|---|---|---:|---:|---|---|
| `BID_ASK_MAKER` | 尽量按买一/卖一做 Maker 挂单 | 当前买一 | 当前卖一，但不得低于买入价上方 | 不保证手续费保本 | 不使用 fee-aware 锚点 |
| `FEE_AWARE_MAKER` | 只把手续费赚回来，优先不亏手续费 | 当前买一，但受锚点限制 | 不低于成本 + 预计卖出手续费保护价 | 是 | 是 |

简单理解：

- `BID_ASK_MAKER` 更像“贴着盘口做买一卖一”，但卖出不能低于买入价。
- `FEE_AWARE_MAKER` 更像“先保护手续费和成本”，宁可等，也不主动低价卖。

---

## 两种策略共同的前置条件

不管用哪种策略，真正下单前都必须满足这些基础条件：

1. 账户处于 `LIVE` 模式。
2. 当前账户已 `解锁 LIVE`。
3. 策略处于 `运行中`。
4. 当前交易对没有无法识别的活动订单。
5. 当前交易对没有成本未知的可交易持仓。
6. 行情流、账户流基本正常。
7. 下单数量和名义金额满足交易所规则，例如最小数量、最小成交额。
8. API 权重没有超过系统安全线。
9. 风控没有触发硬阻断，例如最大持仓、日内回撤、持仓过久等。

所以看到“没有下单”时，不一定是策略不想买，也可能是基础安全检查还没放行。

## `BID_ASK_MAKER · 买一/卖一挂单`

### 适合什么目标

这个策略的目标是尽量贴近买一/卖一挂 Maker 单。

它不追求手续费保本，也不计算完整的手续费保护价；但当前实现里，卖出价格必须高于买入成本价，避免出现“买 1.000，卖 0.999”这种明显倒挂。

### 买入逻辑

当状态是 `IDLE` 且允许入场时：

1. 取当前买一价。
2. 按交易对 tick size 向下取整。
3. 用 `LIMIT_MAKER` 挂买单。

例子：

- 当前买一：`1.0003`
- tick size：`0.0001`
- 买单价格：`1.0003`

如果当前买一变成 `1.00034`，按 tick 规则向下取整后仍可能是 `1.0003`。

卖单完全成交并确认空仓后，`BID_ASK_MAKER` 不会立刻挂下一笔买单；会先等待“卖后买入等待秒数”。

- 默认：`60` 秒。
- 可以在控制台策略配置里调整。
- 填 `0` 表示卖出后不额外等待，下一轮状态机满足条件时即可继续挂买单。

### 当前代码里会看的入场信号

当前代码里的 `BID_ASK_MAKER` 基本只按买一/卖一工作。下面这些信号只计算和展示，不再阻断入场：

- `SELL_TAKER_PRESSURE`：主动卖盘过强。
- `SHORT_TERM_DOWNMOVE`：短时间下跌过快。
- `POST_SELLOFF_COOLDOWN`：刚检测到卖压/下跌后的冷却期。
- `WAIT_FOR_PRICE_RECLAIM`：下跌后价格还没有收复。

它也不看这些完整 fee-aware 保护：

- 顶层盘口太薄：`THIN_TOP_OF_BOOK`
- 五档盘口太薄：`THIN_DEPTH_BOOK`
- 顶层买卖盘强弱不足：`WEAK_TOP_OF_BOOK`
- 短线波动过大：`EXCESS_SHORT_TERM_VOLATILITY`
- 深度数据缺失时的完整深度判断

### 买单挂出后怎么处理

买单挂出后，系统会观察它是否还在买一附近。

如果买单满了配置的买单超时时间：

- 如果它仍然在买一：继续挂着，不撤。
- 如果它已经不在买一：撤掉，等待下一次重新按买一挂。

例子：

买单价格是 `1.0000`。

- 过了 20 秒，当前买一还是 `1.0000`：继续排队。
- 过了 20 秒，当前买一变成 `1.0001`：原买单不在买一，撤掉，等待重新挂。
- 过了 20 秒，当前买一变成 `0.9999`：原买单价格偏高，不再是理想买一，也会撤掉等待。

### 买入成交后怎么卖

买入成交后，卖价按下面规则计算：

```text
卖出价 = max(当前卖一价, 买入均价上方 1 个 tick)
```

也就是说，即使当前卖一低于买入价，系统也不会把卖单挂到买入价以下。

例子 1：卖一高于买入价

- 买入均价：`1.0000`
- 当前卖一：`1.0020`
- tick size：`0.0001`
- 卖出价：`1.0020`

例子 2：卖一低于买入价

- 买入均价：`1.0000`
- 当前卖一：`0.9998`
- tick size：`0.0001`
- 买入价上方 1 tick：`1.0001`
- 卖出价：`1.0001`

例子 3：卖一等于买入价

- 买入均价：`1.0000`
- 当前卖一：`1.0000`
- tick size：`0.0001`
- 卖出价：`1.0001`

这样能避免“越卖越低”的明显倒挂，但不保证扣除手续费后一定不亏。

### 卖单超时后怎么处理

卖单不是永远不动。超过卖单检查时间后，系统会重新评估当前卖一。

重新挂单价格仍然遵守：

```text
新卖出价 = max(当前卖一价, 买入均价上方 1 个 tick)
```

例子：

- 买入均价：`1.0000`
- 原卖单：`1.0020`
- 过了 2 分钟，当前卖一变成 `1.0010`
- 新卖单：`1.0010`

如果当前卖一跌到 `0.9990`：

- 新卖单不会跟到 `0.9990`
- 会挂在 `1.0001`

所以 `BID_ASK_MAKER` 可以降价贴近卖一，但底线是必须高于买入均价。

## `FEE_AWARE_MAKER · 手续费保护 Maker`

### 适合什么目标

这个策略的目标不是追求额外利润，而是优先把手续费赚回来。

它的核心原则是：

```text
下一轮买入不要明显高于上一轮买入锚点；
卖出价格不得低于成本 + 预计卖出手续费保护价。
```

它比 `BID_ASK_MAKER` 更保守。它宁可一直等，也不会为了快速成交主动把卖价砸到手续费保护价以下。

### 买入前会看哪些信号

`FEE_AWARE_MAKER` 会走完整的入场保护，但主动卖盘、短线下跌、下跌后收复这三类只展示，不阻断。

常见判断项如下：

| 原因 | 含义 | 系统行为 |
|---|---|---|
| `STALE_MARKET_DATA` | 买一/卖一行情过期 | 暂不入场 |
| `STALE_DEPTH_DATA` | 五档盘口深度过期 | 暂不入场 |
| `THIN_TOP_OF_BOOK` | 买一或卖一顶层金额太薄 | 暂不入场 |
| `THIN_DEPTH_BOOK` | 五档盘口总深度太薄 | 暂不入场 |
| `WEAK_TOP_OF_BOOK` | 顶层买盘相对卖盘不够强 | 暂不入场 |
| `SELL_TAKER_PRESSURE` | 主动卖盘过强 | 只展示，不阻断入场 |
| `SHORT_TERM_DOWNMOVE` | 短时间价格下跌过快 | 只展示，不阻断入场 |
| `POST_SELLOFF_COOLDOWN` | 刚出现卖压/下跌后的冷却状态 | 只展示，不阻断入场 |
| `WAIT_FOR_PRICE_RECLAIM` | 下跌后尚未收复 | 只展示，不阻断入场 |
| `EXCESS_SHORT_TERM_VOLATILITY` | 短线波动过大 | 暂不入场 |

例子：

控制台显示：

```text
当前状态说明：等待入场信号: WAIT_FOR_PRICE_RECLAIM
```

旧版本里这表示：之前发生过卖压或短线下跌，系统还没看到价格相对低点恢复到要求的幅度，所以暂时不买。

当前版本里，这类卖压/下跌/收复状态不再阻断入场。真正还会挡住 `FEE_AWARE_MAKER` 的，是行情过期、盘口太薄、顶层买卖盘太弱、短线波动过大、买入锚点追高限制等。

### 买入价格

当完整入场信号允许后，系统准备按当前买一挂 Maker 买单。

但 `FEE_AWARE_MAKER` 还会多过一道“买入锚点限制”。

基础买入价：

```text
买入价 = 当前买一价，按 tick size 向下取整
```

然后检查这个买入价是否超过允许追高价。

### 买入锚点是什么

`FEE_AWARE_MAKER` 有两个关键锚点：

1. 上一轮/本轮最高买入价。
2. 本次策略启动以来的初始锚点。

当前实现中，初始锚点优先使用：

```text
手动锚定价格
```

如果没有手动填写，则使用：

```text
最近 5 笔 fee-aware 买入价的平均价
```

如果最近 5 笔也没有，就使用运行态里恢复出来的锚点。

### 允许追高价怎么算

核心公式是：

```text
允许追高价 =
min(
  上一轮最高买入价 * (1 + 单轮最大追高 bps),
  初始锚点 * (1 + 累计最大追高 bps)
)
```

其中：

- `买入锚点等待秒数`：价格高于锚点后，至少等多久才允许检查追高上限。
- `单轮最大追高 bps`：相对上一轮最高买入价，最多允许高多少。
- `累计最大追高 bps`：相对初始锚点，最多允许总共高多少。
- `bps` 是万分之一。`10 bps = 0.10%`，`100 bps = 1%`。

### 买入锚点例子

例子 1：完全不允许追高

- 上一轮最高买入价：`1.0000`
- 初始锚点：`1.0000`
- 单轮最大追高：`0 bps`
- 累计最大追高：`0 bps`
- 当前买一：`1.0001`

结果：

```text
允许最高买入价 = 1.0000
当前买一 1.0001 > 1.0000
不买
```

例子 2：允许单轮追高 10 bps，累计追高 20 bps

- 上一轮最高买入价：`1.0000`
- 初始锚点：`1.0000`
- 单轮最大追高：`10 bps`
- 累计最大追高：`20 bps`

计算：

```text
单轮上限 = 1.0000 * 1.001 = 1.0010
累计上限 = 1.0000 * 1.002 = 1.0020
允许追高价 = min(1.0010, 1.0020) = 1.0010
```

如果当前买一是 `1.0008`，等满锚点等待时间后可以买。

如果当前买一是 `1.0015`，即使等满也不买。

例子 3：累计锚点限制更严

- 上一轮最高买入价：`1.0200`
- 初始锚点：`1.0000`
- 单轮最大追高：`50 bps`
- 累计最大追高：`100 bps`

计算：

```text
单轮上限 = 1.0200 * 1.005 = 1.0251
累计上限 = 1.0000 * 1.010 = 1.0100
允许追高价 = min(1.0251, 1.0100) = 1.0100
```

虽然上一轮买得比较高，但系统仍然会被初始锚点压住，避免越买越高。

例子 4：huaqin-bot 这种情况

假设：

- 当前买一：`0.00947`
- 买入锚点：`0.00922`
- 单轮最大追高：`50 bps`

计算：

```text
单轮允许价约为 0.00922 * 1.005 = 0.0092661
```

当前买一 `0.00947` 明显高于 `0.0092661`，所以即使入场信号恢复，也仍可能被锚点追高限制挡住。

### 买单挂出后怎么处理

买单挂出后，系统会持续检查：

1. 买单是否还在买一。
2. 当前买一是否仍在 fee-aware 允许买入上限内。

如果买单已满超时时间：

- 仍在买一：继续挂单。
- 不在买一：撤单等待重新挂。
- 当前买一高于允许买入上限：撤单等待价格回落。
- 已经挂着的是较低安全买单，且没有超过允许上限：保留较低 Maker 买单继续排队。

例子：

- 允许最高买入价：`1.0000`
- 当前已有买单：`0.9998`
- 最新买一涨到：`1.0003`

系统不会追到 `1.0003`，会保留较低买单或撤单等待回落。

### 买入成交后怎么卖

`FEE_AWARE_MAKER` 的卖出底线是手续费保护价。

核心计算：

```text
持仓成本单价 = 当前持仓成本 / 当前持仓数量
手续费保护价 = 持仓成本单价 / (1 - 预计 maker 卖出费率)
最终卖出价 = max(手续费保护价, 当前卖一价)
```

最后再按 tick size 向上取整。

手续费率来源优先级：

1. 策略里手动配置的 `Maker 费率 bps`。
2. 交易所返回的当前账户/交易对实际 commission rate。
3. 读取失败时，用系统保守默认费率。

例子 1：卖一高于手续费保护价

- 买入成本单价：`1.0000`
- maker 卖出费率：`10 bps = 0.10%`
- 手续费保护价约：`1.0011`
- 当前卖一：`1.0030`

结果：

```text
卖出价 = 1.0030
```

例子 2：卖一低于手续费保护价

- 买入成本单价：`1.0000`
- maker 卖出费率：`10 bps`
- 手续费保护价约：`1.0011`
- 当前卖一：`1.0005`

结果：

```text
卖出价 = 1.0011 或按 tick 向上后的价格
```

系统不会为了贴卖一而挂到 `1.0005`。

例子 3：实际看到的 xiaoyuan 行为

- 买入：`0.00941000`
- 当前活动卖单：`0.00943000`

这是因为系统按成本、预计 maker 卖出手续费和当前卖一取更高值后，向上取整得到了 `0.00943000`。

### 卖单超时后怎么处理

`FEE_AWARE_MAKER` 的卖单超时，不代表会主动砸价卖。

卖单到检查时间后：

1. 重新计算当前手续费保护价。
2. 再看当前卖一。
3. 用 `max(手续费保护价, 当前卖一)` 得到新的安全卖价。

如果当前挂单价格已经等于新的安全卖价：

```text
不撤单，继续排队。
```

如果安全卖价变化了：

```text
撤掉旧卖单，重新挂到新的安全卖价。
```

关键点：

```text
无论怎么重新挂，都不会低于手续费保护价。
```

例子：

- 买入成本单价：`1.0000`
- 手续费保护价：`1.0011`
- 原卖单：`1.0030`
- 2 分钟后当前卖一跌到：`1.0008`

结果：

```text
新卖单不会挂 1.0008
新卖单会挂 1.0011 或按 tick 向上后的价格
```

这就是“用时间换成交”，不是主动低价卖。

## 重启、停止、异常订单怎么处理

### 正常空仓重启

如果账户：

- 当前交易对无活动订单；
- 当前交易对无可交易持仓；
- 本地运行态能正常读取；

系统可以进入 `IDLE`，等待下一次入场信号。

### 有本进程记录的活动卖单

如果重启后发现交易所有一个活动卖单，并且它满足：

- 本地运行态记录是 `SELLING`；
- 本地记录的 `orderId` 匹配交易所活动订单；
- `clientOrderId` 也匹配；
- 订单方向是 `SELL`；
- 交易所显示未部分成交；
- 本地每日账本里有对应持仓成本；
- 交易所余额与本地持仓数量能对上；

系统可以恢复这个卖单，继续管理。

### 有活动订单但对不上

如果交易所有活动订单，但本地运行态无法确认它就是本进程管理的订单，会保护停机：

```text
发现未由本进程恢复的活动订单，需先人工对账
```

这种情况不能让程序自动接管，因为它不知道：

- 这个订单是谁挂的；
- 成本是多少；
- 是不是已经部分成交；
- 本地账本是否该更新；
- 继续管理会不会重复卖、重复买或算错成本。

处理方式应该是先人工对账：

1. 去交易所确认当前活动订单。
2. 确认当前标的余额。
3. 确认最近成交记录。
4. 判断订单是否要保留、撤销、或手工处理。
5. 对账完成后再重启/启动策略。

### 有可交易持仓但成本未知

如果启动时发现当前交易对有可交易持仓，但本地没有可靠成本，系统会拒绝自动接管：

```text
发现既有可交易标的持仓，成本未知；拒绝自动接管
```

这是为了避免系统不知道保本价，却贸然卖出。

尤其对 `FEE_AWARE_MAKER` 来说，成本未知就无法计算手续费保护价。

### 收到未关联订单成交回报

如果账户流推送了一个成交事件，但订单 ID 不属于当前进程正在管理的订单，系统会保护停机：

```text
收到未关联订单的成交回报，需人工对账
```

这通常说明：

- 有人在交易所手工下单；
- 或重启前的订单没有被本地恢复；
- 或本地运行态与交易所状态出现偏差。

这种情况也需要人工确认成交、仓位、成本和活动订单。

## 常见控制台状态怎么读

### `运行中，等待入场信号`

策略已运行，但还没有满足买入条件。

对 `FEE_AWARE_MAKER` 来说，可能是盘口太薄、行情过期、顶层买卖盘太弱、波动过大、锚点限制等任一条件未满足。

对 `BID_ASK_MAKER` 来说，主动卖压、短线下跌、下跌后等待收复不再挡住入场。

### `等待入场信号: WAIT_FOR_PRICE_RECLAIM`

旧版本里，这表示之前发生过下跌或主动卖压，系统正在等价格从低点收复。

当前版本里，这类状态不再作为入场阻断原因。如果仍看到它，通常说明服务还没部署到新版本，或页面还在显示旧状态。

### `暂停新买入：当前买一高于买入锚点`

这是 `FEE_AWARE_MAKER` 的追高限制。

意思是当前买一价比上一轮/初始锚点高太多，系统认为继续买会造成“越买越高”。

### `手续费保护卖单已挂出`

这是 `FEE_AWARE_MAKER` 的正常卖出状态。

卖价已经按成本和预计手续费保护过。

### `卖单检查后按手续费保护价继续排队`

卖单超时检查触发了，但系统重新挂出的价格仍不低于手续费保护价。

### `BUY 成交后按卖一/买入价上方挂限价卖单`

这是 `BID_ASK_MAKER` 的正常卖出状态。

卖价贴近卖一，但不会低于买入均价上方。

---

## 选择建议

如果你的目标是：

```text
尽量减少越买越高，卖出至少把手续费保护住
```

优先用：

```text
FEE_AWARE_MAKER
```

如果你的目标是：

```text
更贴近买一/卖一，允许不严格手续费保本，但卖价必须高于买价
```

可以用：

```text
BID_ASK_MAKER
```

如果遇到“为什么一直不下单”，排查顺序建议是：

1. 看是否 `running=true`。
2. 看是否 `LIVE` 且已解锁。
3. 看 `statusReason`。
4. 看 `entrySignal.reason`。
5. 如果是 `FEE_AWARE_MAKER`，再看买入锚点、当前买一、单轮最大追高、累计最大追高。
6. 看是否有活动订单或成本未知持仓导致人工对账。

## 两个完整场景例子

### 场景 A：`BID_ASK_MAKER`

盘口：

```text
买一 1.0000
卖一 1.0002
```

系统挂买：

```text
BUY 1.0000
```

买入成交后，盘口变成：

```text
买一 0.9998
卖一 0.9999
```

因为卖一低于买入价，系统不会挂 `0.9999`，而是挂：

```text
SELL 1.0001
```

如果 2 分钟后卖一回到 `1.0003`，系统可以改挂：

```text
SELL 1.0003
```

### 场景 B：`FEE_AWARE_MAKER`

配置：

```text
买入锚点等待秒数：1800
单轮最大追高 bps：10
累计最大追高 bps：20
```

上一轮最高买入价：

```text
1.0000
```

初始锚点：

```text
1.0000
```

当前买一：

```text
1.0015
```

允许价：

```text
单轮上限 1.0010
累计上限 1.0020
最终允许最高 1.0010
```

因为 `1.0015 > 1.0010`，所以不买。

如果价格回落到 `1.0008`，并且其它入场信号也通过，系统可以挂：

```text
BUY 1.0008
```

买入成交后，假设 maker 卖出费率是 `10 bps`，手续费保护价约为：

```text
1.0019
```

如果当前卖一是 `1.0010`，系统不会挂 `1.0010`，而是挂：

```text
SELL 1.0019 或按 tick 向上后的价格
```

如果当前卖一是 `1.0030`，系统会挂：

```text
SELL 1.0030
```

因为它高于手续费保护价。
