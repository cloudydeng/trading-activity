# 两种 Maker 策略产品说明

本文用产品和运营能直接理解的方式，说明当前系统中两种策略的真实行为：

- `BID_ASK_MAKER · 买一/卖一挂单`
- `FEE_AWARE_MAKER · 手续费保护 Maker`

本文回答五个核心问题：什么时候买、买什么价格、买到后怎么卖、订单长时间不成交怎么办、停止或重启后怎么办。

> 本文描述当前代码行为，不代表收益承诺，也不构成交易建议。

---

## 1. 先看结论

两种策略的买入方式基本相同，主要差别在“是否限制追高”和“刚买入后的第一张卖单如何定价”。

| 对比项 | `BID_ASK_MAKER` | `FEE_AWARE_MAKER` |
|---|---|---|
| 产品定位 | 更直接地贴着买一、卖一成交 | 先尝试覆盖手续费，再考虑快速退出 |
| 买单价格 | 当前买一 | 当前买一，但受买入锚点限制 |
| 买单类型 | `LIMIT_MAKER` | `LIMIT_MAKER` |
| 是否限制越买越高 | 否 | 是 |
| 初始卖价 | 当前卖一和“买入价上方 1 tick”取较高值 | 当前卖一和“手续费保护价”取较高值 |
| 初始卖单类型 | 普通 `LIMIT` | `LIMIT_MAKER` |
| 卖单超时后的目标价 | 最新卖一 | 最新卖一 |
| 超时后是否继续保护买入价/手续费 | 否 | 否 |
| 超时重挂类型 | 普通 `LIMIT` | `LIMIT_MAKER` |

一句话理解：

- `BID_ASK_MAKER`：买一买，卖一卖，初始卖价至少比买入价高 1 个最小价格单位。
- `FEE_AWARE_MAKER`：买一买，但不允许无限追高；刚买到时先挂手续费保护卖价。
- 两种策略的卖单一旦超过检查时间，都会把“尽快释放仓位”放在第一位，不再坚持原来的价格底线。

## 2. 产品需要知道的盘口名词

### 买一

当前市场里最高的买入报价。

例如：

```text
买一 1.0000
```

表示当前有人愿意以 `1.0000` 买。

### 卖一

当前市场里最低的卖出报价。

例如：

```text
卖一 1.0002
```

表示当前有人愿意以 `1.0002` 卖。

### tick

交易所允许的最小价格变化单位。

如果 tick 是 `0.0001`，合法价格可以是 `1.0000`、`1.0001`、`1.0002`，不能是 `1.00015`。

系统所有买卖价格最终都会按 tick 取整：

- 买单通常向下取整，避免超过计划买价。
- 需要保护底线的卖单向上取整，避免低于保护价。

### `LIMIT_MAKER` 和普通 `LIMIT`

- `LIMIT_MAKER`：只允许挂在订单簿里，不允许一提交就立即吃掉对手盘；如果会立即成交，交易所可能拒绝该订单。
- 普通 `LIMIT`：指定一个限价，可以挂在订单簿里，也可能因为市场变化立即成交。

## 3. 两种策略共同的完整流程

```text
人工启动账户
  ↓
确认账户、行情、订单、持仓和风控安全
  ↓
空仓时按买一挂 LIMIT_MAKER 买单
  ↓
买入全部成交，或部分成交已达到可卖条件
  ↓
撤掉剩余买单，按所选策略挂第一张卖单
  ↓
卖单成交并确认空仓
  ↓
等待“卖后买入等待秒数”
  ↓
进入下一轮
```

两种策略都不会同时无序地挂多轮买卖单。系统会先完成或处理当前订单，再进入下一阶段。

### 默认时间

| 配置 | 未单独配置时的默认值 | 含义 |
|---|---:|---|
| 买单超时 | 20 秒 | 买单挂够这个时间后，检查它是否仍在买一 |
| 卖单检查 | 120 秒 | 卖单挂够这个时间后，检查它是否仍在卖一 |
| 卖后买入等待 | 60 秒 | 卖完并确认空仓后，等待多久才开始下一轮 |

每个账户、每个交易对都可以单独配置这些时间。

## 4. 共同的买入规则

### 4.1 买入价格

基础买价都是：

```text
买入价 = 当前买一价
```

然后按 tick 向下取整，并使用 `LIMIT_MAKER` 挂单。

例子：

```text
当前买一：1.00034
tick：0.0001
最终买价：1.0003
```

### 4.2 哪些行情指标不再阻止买入

当前两种策略都不再因为下面这些技术指标暂停买入：

- 主动卖盘过强；
- 短线下跌；
- 下跌后尚未收复；
- 买一力量不足；
- 顶层盘口较薄；
- 五档深度较薄；
- 短线波动较大。

这些指标即使仍出现在诊断数据中，也只用于观察，不决定是否挂买单。

### 4.3 真正会阻止买入的情况

下面这些属于安全底线，仍然会阻止买入：

- 账户没有人工启动；
- 服务器没有开启真实交易开关；
- 账户成交流或必要行情不可用；
- 当前交易对存在无法安全接管的活动订单；
- 当前存在成本未知或数量对不上的可交易持仓；
- API 请求权重达到安全线；
- 下单数量或金额不满足交易所最小规则；
- 风控触发，例如最大持仓、日内回撤或库存持有超时；
- 今日成交量达到该账户配置的上限；
- 账户 BNB 价值低于 `1 USDT`；
- 使用 `FEE_AWARE_MAKER` 时，当前买一超过锚点允许价。

因此，“账户显示运行中”不等于“一定马上产生买单”。运行中只表示状态机正在工作，真正下单还需要通过这些安全检查。

### 4.4 买单挂久了怎么办

买单达到“买单超时”后：

- 当前订单仍在买一：保留原单，继续排队。
- 当前订单已经不在买一：撤掉旧单，等待按新的买一重新挂。
- 不会改成市价单追买。

例子：

```text
原买单：1.0000
20 秒后买一仍是 1.0000
结果：保留原单
```

```text
原买单：1.0000
20 秒后买一变成 1.0001
结果：撤掉原单，下一次按最新买一重新挂
```

### 4.5 买单只成交了一部分

如果已买到的部分已经达到交易所最小可卖条件，系统会：

1. 撤掉尚未成交的买单；
2. 对账实际成交数量和手续费；
3. 立即进入卖出阶段。

如果已成交部分太小，暂时无法形成有效卖单，系统会把它标为小额库存，等待后续处理，不会提交交易所一定会拒绝的卖单。

## 5. `BID_ASK_MAKER` 产品行为

### 5.1 适用目标

这个策略更强调贴近盘口、提高成交机会。

它没有买入锚点，也不保证扣除全部手续费后保本。它只在第一张卖单上保留一个简单底线：卖价必须高于买入均价。

### 5.2 第一张卖单怎么算

```text
初始卖价 = max(当前卖一, 买入均价上方 1 tick)
```

第一张卖单使用普通 `LIMIT`。

#### 例子 A：卖一高于买价

```text
买入均价：1.0000
当前卖一：1.0020
tick：0.0001
初始卖价：1.0020
```

#### 例子 B：卖一低于买价

```text
买入均价：1.0000
当前卖一：0.9998
买入价上方 1 tick：1.0001
初始卖价：1.0001
```

此时不会一开始就按 `0.9998` 亏价卖出。

### 5.3 卖单超时怎么办

卖单达到“卖单检查”时间后，系统只比较两件事：原订单价格和最新卖一。

```text
如果原订单价 == 最新卖一：
    不撤单，保留排队位置，重新开始下一轮计时

如果原订单价 != 最新卖一：
    撤掉旧单
    对账旧单是否有部分成交
    按最新卖一重新挂普通 LIMIT 卖单
```

超时后的目标价只有一个：

```text
新卖价 = 最新卖一
```

超时后不再使用“买入价上方 1 tick”的底线。

#### 例子 C：原单仍在卖一

```text
原卖单：1.0020
120 秒后最新卖一：1.0020
结果：不撤单，重新计时 120 秒
```

#### 例子 D：卖一下移

```text
买入均价：1.0000
原卖单：1.0020
120 秒后最新卖一：0.9990
结果：撤掉 1.0020，按 0.9990 重新挂卖单
```

这里可能产生亏损。原因是卖单已经长时间没有成交，超时阶段的产品目标已经从“守住买价”切换为“尽快卖出并释放资金”。

#### 例子 E：暂时拿不到卖一

系统不会盲目撤单，而是保留原卖单，等下一个“卖单检查”周期再判断。

## 6. `FEE_AWARE_MAKER` 产品行为

### 6.1 适用目标

这个策略增加两层保护：

1. 买入时限制价格不断上移，减少“越买越高”；
2. 买入后的第一张卖单先尝试覆盖持仓成本和预计卖出手续费。

它不额外追求利润。手续费保护价就是初始卖出的主要目标。

### 6.2 买入锚点是什么

系统同时使用两个锚点：

- 上一轮最高买入价：控制下一轮相对上一轮最多追高多少。
- 初始锚点：控制本次策略运行期间累计最多追高多少。

初始锚点的来源顺序：

1. 产品或运营手动填写的锚定价格；
2. 没有手动填写时，取最近 5 笔 `FEE_AWARE_MAKER` 买入价的平均值；
3. 最近成交不足时，使用运行状态能够安全恢复出的锚点。

控制台会展示系统推荐锚点。未修改时继续使用系统自动值；手动填写后会同时展示“手动值 / 推荐值”。

### 6.3 允许最高买价怎么算

```text
单轮上限 = 上一轮最高买入价 × (1 + 单轮最大追高 bps)

累计上限 = 初始锚点 × (1 + 累计最大追高 bps)

最终允许最高买价 = min(单轮上限, 累计上限)
```

`bps` 是万分之一：

- `10 bps = 0.10%`
- `50 bps = 0.50%`
- `100 bps = 1.00%`

当当前买一不高于原买入锚点时，可以直接进入正常买入检查。

当当前买一高于原买入锚点时，先等待“买入锚点等待秒数”；等待结束后，也只有不超过最终允许最高买价时才能买。

默认配置：

- 买入锚点等待：`1800` 秒；
- 单轮最大追高：`0 bps`；
- 累计最大追高：未配置时跟随单轮值。

默认 `0 bps` 的含义是：即使等待结束，也不允许买得比锚点更高，只能等价格回落。

#### 例子 A：完全不追高

```text
上一轮最高买价：1.0000
初始锚点：1.0000
单轮最大追高：0 bps
累计最大追高：0 bps
当前买一：1.0001
```

结果：当前买一高于允许价 `1.0000`，不挂买单。

#### 例子 B：允许小幅追高

```text
上一轮最高买价：1.0000
初始锚点：1.0000
单轮最大追高：10 bps
累计最大追高：20 bps
```

计算：

```text
单轮上限：1.0010
累计上限：1.0020
最终允许最高买价：1.0010
```

- 当前买一 `1.0008`：等待时间满足后可以买。
- 当前买一 `1.0015`：超过最终上限，等待再久也不买。

#### 例子 C：累计上限更严格

```text
上一轮最高买价：1.0200
初始锚点：1.0000
单轮最大追高：50 bps
累计最大追高：100 bps
```

计算：

```text
单轮上限：1.0251
累计上限：1.0100
最终允许最高买价：1.0100
```

即使上一轮已经买到 `1.0200`，系统也不会继续以它为基础不断向上追价；累计锚点会把最高买价限制在 `1.0100`。

### 6.4 第一张卖单怎么算

```text
持仓成本单价 = 当前持仓成本 ÷ 当前持仓数量

手续费保护价 = 持仓成本单价 ÷ (1 - 预计卖出费率)

初始卖价 = max(当前卖一, 手续费保护价)
```

最终价格按 tick 向上取整，第一张卖单使用 `LIMIT_MAKER`。

手续费率来源顺序：

1. 当前策略手动填写的 Maker 费率；
2. 交易所返回的当前账户、当前交易对真实费率；
3. 无法读取时使用系统保守默认值。

#### 例子 D：卖一已经足够高

```text
持仓成本单价：1.0000
预计卖出费率：10 bps
手续费保护价：约 1.0011
当前卖一：1.0030
初始卖价：1.0030
```

#### 例子 E：卖一低于手续费保护价

```text
持仓成本单价：1.0000
预计卖出费率：10 bps
手续费保护价：约 1.0011
当前卖一：1.0005
初始卖价：约 1.0011，再按 tick 向上取整
```

系统不会在第一张卖单上直接降到 `1.0005`。

### 6.5 卖单超时怎么办

超时处理与 `BID_ASK_MAKER` 的判断原则相同：

```text
如果原订单价 == 最新卖一：
    保留原 LIMIT_MAKER 卖单，重新开始下一轮计时

如果原订单价 != 最新卖一：
    撤掉旧单
    对账已成交数量和剩余库存
    按最新卖一重新挂 LIMIT_MAKER 卖单
```

超时后的目标价为：

```text
新卖价 = 最新卖一
```

此时不再强制使用手续费保护价。

#### 例子 F：手续费保护价长期无法成交

```text
持仓成本单价：1.0000
手续费保护价：1.0011
原卖单：1.0011
120 秒后最新卖一：0.9995
```

结果：撤掉原卖单，按最新卖一 `0.9995` 重新挂 `LIMIT_MAKER`。

这次卖出可能无法赚回手续费，也可能产生价差亏损。超时机制的目的就是避免为了守手续费保护价而长期占用仓位。

如果原卖单本身就是最新卖一，则不撤单，也不会因为“已经超时”而反复丢失排队位置。

## 7. 每日成交量上限

每个账户、每个交易对可以配置每日真实成交量上限，默认是 `510 USDT`，按 UTC 日期计算。

买入和卖出都计入成交量。

例如一轮交易：

```text
买入成交额：12 USDT
卖出成交额：约 12 USDT
本轮累计成交量：约 24 USDT
```

达到或超过上限后：

- 空仓：立即停止当前账户。
- 正在挂买单：撤销买单并对账，然后停止。
- 已持仓或正在卖出：停止新买入，但保留退出流程；卖完并确认空仓后自动停止。

因为已有仓位必须先卖完，所以最终成交量可能略高于配置上限。

UTC 日期进入新的一天后，成交量重新计算；但前一天已自动停止的账户不会自行启动，仍需人工启动。

## 8. BNB 余额保护

系统每 30 秒左右检查一次账户 BNB 总余额，并按 `BNBUSDT` 最新价换算成 USDT。

当 BNB 价值低于 `1 USDT`：

- 空仓：立即停止当前账户。
- 正在挂买单：撤销买单并对账。
- 已持仓或正在卖出：不直接撤掉退出卖单，先完成卖出，确认空仓后停止。

这个规则只影响 BNB 不足的账户，不影响其他账户。

如果 BNB 余额或价格暂时读取失败，系统沿用最近一次有效结果；从未取得有效结果时，不会把“未知”误判成低于 `1 USDT`。

## 9. 停止、重启和持仓恢复

### 9.1 人工点击“停止当前”

人工停止会尝试撤销当前活动订单并核对订单和余额。

- 空仓且没有活动订单：安全停止，状态回到 `IDLE`。
- 仍有可交易持仓：不能假装已经安全空仓，控制台会明确提示仍有持仓或进入保护状态。
- 只有不足交易所最小卖出条件的小额余额：作为粉尘保留。

人工停止与“达到成交量/BNB 限制后的自动停止”不同：自动停止会优先让已经存在的 SELL 完成，再停止账户。

### 9.2 服务重启

服务重启后，账户默认不会自动开始新一轮交易，必须人工启动。

系统不会把本地旧持仓当作真实持仓。余额、今日成交、手续费和今日盈亏以交易所远程数据为准。

### 9.3 有持仓但没有活动订单

人工重新启动时，如果交易所存在可卖持仓，系统会尝试用“今天 UTC 的远程成交记录”恢复：

- 未平仓数量；
- 持仓成本；
- 实际手续费；
- 与交易所当前余额是否一致。

能够恢复且数量一致时，系统进入 `SELLING`，按当前策略重新挂卖单。

例如：

```text
今天策略买入后仍持仓
→ 人工停止，卖单被撤销
→ 再次启动当前账户
→ 系统从今天的交易所成交记录恢复成本
→ 重新进入卖出阶段
```

### 9.4 为什么有时会要求人工对账

出现下面任一种情况时，系统不会猜测订单和成本：

- 交易所有活动订单，但不能确认是当前进程管理的订单；
- 有持仓，但今天的远程成交无法还原成本；
- 远程成交还原的数量与交易所余额不一致；
- 收到不属于当前进程订单的成交回报；
- 撤单结果或成交明细无法确认。

典型提示：

```text
发现未由本进程恢复的活动订单，需先人工对账
```

```text
发现既有可交易标的持仓，但今日远程成交无法还原成本或与交易所余额不一致；拒绝自动接管
```

这时产品或运营需要在交易所确认：活动订单、当前余额、最近成交、订单是否部分成交，然后再决定保留、撤销或手工处理。

## 10. 控制台状态怎么理解

| 控制台内容 | 产品含义 |
|---|---|
| `FEE_AWARE_MAKER` | 当前使用手续费保护策略 |
| `BID_ASK_MAKER` | 当前使用买一/卖一策略 |
| `运行中`（绿色） | 状态机正在运行，不代表一定马上下单 |
| `已停止`（红色） | 当前账户不会发起新交易 |
| `IDLE` | 当前没有正在管理的买卖单 |
| `BUYING` | 当前正在管理买单 |
| `SELLING` | 当前正在管理卖单或持仓退出 |
| `HALTED` | 因异常或安全原因进入保护停机，需要查看状态说明 |

策略名称和策略阶段不是同一个概念。例如：

```text
策略名称：FEE_AWARE_MAKER
策略阶段：SELLING
运行状态：运行中
```

这表示账户正在使用手续费保护策略管理一张卖单。

---

## 11. 产品选型建议

### 选择 `BID_ASK_MAKER`

适合更关注贴近盘口和成交机会，并且可以接受：

- 没有买入追高锚点；
- 初始卖单不做完整手续费保护；
- 卖单超时后可能低于买入价成交。

### 选择 `FEE_AWARE_MAKER`

适合更关注控制追高和第一阶段手续费保护，并且可以接受：

- 当前价格超过锚点时可能长时间没有买单；
- 手续费保护卖价可能需要更久才能成交；
- 卖单超时后仍会切换为最新卖一，保护价不再是硬底线。

### 两种策略都不能保证的事

两种策略都不能保证不亏损，原因包括：

- 买入后市场下跌；
- 卖单超时后按较低卖一退出；
- 普通 `LIMIT` 可能按 taker 成交；
- 手续费折算和实际成交价格变化；
- 部分成交、滑点、盘口变化和交易所延迟。

`FEE_AWARE_MAKER` 只是在第一张卖单上尝试保护成本和手续费，不等于整轮交易一定保本。

## 12. “为什么没有下单”排查顺序

产品和运营按以下顺序查看即可：

1. 账户是否显示绿色“运行中”。
2. 当前阶段是否已经是 `BUYING` 或 `SELLING`。
3. 是否存在活动订单或可交易持仓。
4. 状态说明是否要求人工对账。
5. 今日成交量是否达到上限。
6. BNB 价值是否低于 `1 USDT`。
7. API 权重、账户流和行情是否正常。
8. 如果是 `FEE_AWARE_MAKER`，检查当前买一是否超过锚点允许价。
9. 检查下单金额是否满足交易所最小成交额和数量精度。

不要再把“主动卖盘过强”“买一力量不足”“短线下跌”等旧行情指标当作当前版本不下单的原因。
